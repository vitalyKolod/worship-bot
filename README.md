# Worship Bot 🎶

Бот для команды прославления: хранит песни (тональность, темп, капо, жанр, заметки)
и отвечает на вопросы о них прямо в группе или в личном чате, без обращения через @.

## Стек

- [grammY](https://grammy.dev) + TypeScript
- MongoDB (Mongoose)
- [@grammyjs/conversations](https://grammy.dev/plugins/conversations) — пошаговый флоу добавления песни

## Быстрый старт

### 1. Установи зависимости

```bash
npm install
```

### 2. Получи токен бота

Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → скопируй токен.

### 3. Подними MongoDB

Проще всего — бесплатный кластер на [MongoDB Atlas](https://www.mongodb.com/atlas)
(free tier M0 хватит с запасом). Либо локально:

```bash
docker run -d -p 27017:27017 --name worship-mongo mongo:7
```

### 4. Заполни `.env`

```bash
cp .env.example .env
```

И впиши `BOT_TOKEN`, `MONGODB_URI`, свой `SUPER_ADMIN_IDS` (узнать telegram_id — написать [@userinfobot](https://t.me/userinfobot)).

Настройки расписания:

```env
APP_TIMEZONE=Europe/Moscow
REMINDER_INTERVAL_MS=60000
REMINDER_TEST_MODE=false
```

`REMINDER_TEST_MODE=true` разрешает администраторам команд тестовую команду
`/test_rehearsal_reminder`. В production оставляй значение `false`.

### 5. Запусти

```bash
npm run dev      # разработка, с автоперезапуском
# или
npm run build && npm start   # production
```

## Как пользоваться

1. Напиши боту в личку `/start`, пройди регистрацию и выбери одну или несколько ролей.
2. Открой «Мои команды» → «Создать команду» и введи её название.
3. Добавь бота в Telegram-группу команды и сделай его администратором.
4. В BotFather отключи privacy mode: `/setprivacy` → выбери бота → `Disable`, иначе Telegram не отдаст боту обычные сообщения группы.
5. В группе выполни `/setup`, выбери созданную команду и подтверди подключение.
6. Участники вступают через опубликованную deep-link кнопку; бот проверяет их присутствие в Telegram-группе.
7. Владелец добавляет песню через `/add_song`, а дополняет её позже через `/edit_song`.
8. Дальше пишите в чат, например: *«какая тональность у песни Благодать»* или
   *«какие аккорды у песни Jesus»* — бот найдёт песню и покажет всю заполненную информацию.
   Такие же вопросы можно задавать боту в личном чате — поиск пройдёт по всем доступным пользователю командам.

### Массовый импорт начального каталога

После создания команды и подключения Telegram-группы через `/setup` сначала посмотри
названия и id доступных команд:

```bash
npm run import:songs
```

Затем выполни проверку без записи и сам импорт:

```bash
npm run import:songs -- --team-name "Название команды"
npm run import:songs -- --team-name "Название команды" --commit
```

Скрипт можно запускать повторно: песни с уже существующими названиями он пропускает.
Для всех песен начального каталога установлен размер `4/4`, а неизвестная тональность
записана как `не знаю`.

Распознавание вопросов работает локально по фразам и ключевым словам. Например, бот понимает
«кто поёт Благодать», «как играем Way Maker» и «какие песни у нас есть». Сообщения не
отправляются во внешние сервисы. На сообщения об опоздании или отсутствии бот отвечает одной
из заготовленных музыкальных шуток.

## Расписание и команда

Основные команды работают и в привязанной группе, и в личном чате. Если в личке доступно
несколько команд, бот сначала попросит выбрать нужную.

- `/rehearsal`, `/rehearsals` — ближайшая репетиция и список;
- `/rehearsal_add`, `/rehearsal_edit`, `/rehearsal_cancel` — управление репетициями;
- `/services`, `/service_add`, `/service_edit`, `/service_cancel` — управление служениями;
- `/today`, `/next` — события сегодня и ближайшее событие;
- `/lineup`, `/setlist` — состав и сет-лист ближайшего служения.

В карточке репетиции участник может ответить «Буду», «Опоздаю» или «Не смогу».
Ответ повторно не дублируется, а обновляется. Для опоздания доступны 10, 20, 30 минут и
ручной ввод. Администратор видит сводку и список не ответивших.

Служение хранит состав и упорядоченный сет-лист из существующей базы `Song`. Кнопками можно
назначать и убирать участников, добавлять/удалять песни, менять порядок и тональность.

При добавлении репетиции или служения бот обязательно открывает финальный блок состава.
Администратор отмечает позиции галочками (`Вокал 1/2/3`, `Электрогитара 1/2`, барабаны,
клавиши и другие), после чего бот по очереди спрашивает имя для каждой позиции. Эти имена
сохраняются как текст и не обязаны принадлежать зарегистрированным участникам. В preview
состав можно полностью выбрать заново через кнопку «Изменить состав».

## Сообщения в группе

Парсер работает локально, без AI. Изменение расписания и состава доступно только owner,
admin или leader. Такие сообщения сначала создают временное предложение с кнопками, а запись
в БД меняется только после «Подтвердить»:

- `репетиция завтра в 19:00`;
- `перенесем репетицию на субботу в 18:00`;
- `репетиции завтра не будет`;
- `состав на воскресенье: барабаны Виталий`.

Имена в составе из группового сообщения также не сверяются с регистрацией. Например,
`Барабаны — Виталик`, `Электро — Макс`, `Клавиши — Денис` сохраняются как введённый текст.

Сообщения участника `я опоздаю на 20 минут` и `я сегодня не смогу` связываются только с
близкой репетицией (не дальше 36 часов). Для отсутствия на служении бот проверяет назначение
в составе и предлагает администратору подобрать замену. Состав меняется только после того,
как кандидат подтвердит замену в личке.

## Напоминания

Запускается один scheduler. Он атомарно отмечает отправленные напоминания в `Rehearsal`,
поэтому перезапуск процесса не создаёт повторов. Уведомления за 24 и 2 часа отправляются
только в Telegram-группу, привязанную к конкретной команде.

## Ручная проверка

1. В личке отправь `/service_add`, выбери команду и введи `30.08.2026`, `10:00`, название,
   место и время саундчека. После подтверждения открой `/lineup` и `/setlist`.
2. Отправь `/rehearsal_add`, затем `28.08.2026`, `19:00`, `Основной зал`, `/skip` и подтверди.
3. В группе напиши `Давайте репетицию завтра в 19:00`. До нажатия кнопки записи быть не
   должно; после `✅ Подтвердить` должна появиться новая репетиция.
4. Напиши `Давайте перенесем репетицию на субботу в 18:00`, проверь preview «было/стало» и
   подтверди.
5. Напиши `Репетиции завтра не будет`, затем подтверди отмену. Запись должна получить статус
   `cancelled`, а не удалиться.
6. Участником команды напиши `Я опоздаю на 20 минут`. Для репетиции в ближайшие 36 часов
   сохранится ответ `late` и `lateMinutes=20`.
7. Администратором напиши многострочный состав: `Состав на воскресенье:` и далее
   `барабаны Виталий`, `бас Дима`, `клавиши Андрей`, `вокал Аня`. Состав сохранится только
   после подтверждения. Неизвестные и неоднозначные имена должны остановить операцию.
8. Проверь `/today`, `/next`, `/rehearsal`, `/lineup` и `/setlist` обычным участником.
9. Проверь права: обычный участник не должен подтвердить создание, перенос, отмену или
   изменение состава.
10. Для reminders временно установи `REMINDER_TEST_MODE=true`, перезапусти бота и в группе
    выполни `/test_rehearsal_reminder`. После проверки верни `false`.

## Структура проекта

```
src/
├── bot/
│   ├── index.ts              # сборка бота: middlewares + composers
│   ├── context.ts            # общий тип MyContext (conversations + team + session)
│   ├── middlewares/
│   │   ├── teamContext.ts    # резолвит группу → команду (ctx.team)
│   │   └── auth.ts           # проверка прав админа
│   ├── conversations/
│   │   ├── addSongFlow.ts    # пошаговое добавление песни
│   │   └── scheduleFlows.ts  # репетиции, служения, опоздания, тональность сет-листа
│   └── handlers/
│       ├── schedule.ts       # команды и callback-кнопки расписания
│       ├── private/menu.ts   # /start, /add_song в личке
│       └── group/
│           ├── setup.ts      # /start в группе — регистрирует команду
│           ├── messageIntents.ts # безопасные предложения из обычного текста
│           ├── songQuery.ts  # распознаёт вопросы про песни
│           └── jokes.ts      # шутки над опоздавшими
├── services/                 # бизнес-логика, без Telegram-специфики
│   ├── rehearsal.service.ts
│   ├── worship-service.service.ts
│   ├── date-parser.service.ts
│   ├── message-intent.service.ts
│   ├── notification.service.ts
│   └── reminder.service.ts
├── models/                   # команды, песни, события, ответы и подтверждения
└── index.ts                  # entry point: подключение к БД + запуск бота
```

Новая миграция не требуется: существующие схемы и данные не изменяются. Новые коллекции и
индексы создаются через `syncIndexes()` при запуске.

## Дальнейшие шаги (не в этом MVP)

- Личный кабинет команды (веб) — модель `TeamMember` с ролями уже заложена под это
- Транскрибация песен
- Подбор инструментов/аранжировки
- Мульти-команды у одного пользователя — тоже уже заложено в схему (`User` ↔ `Team` через `TeamMember`, many-to-many)
